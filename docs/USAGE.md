# User Guide

## 1. Environment Requirements

* Python Version: Requires Python version `3.12` or higher (specified in `.python-version` and `requires-python` in `pyproject.toml`).
* Operating System: No specific operating system requirements are defined in the source code or configurations. However, standard Python running environments are supported.
* Prerequisites:
  * Package and virtual environment manager `uv` (as the project uses `uv.lock` for dependency management).
* Other hardware/software requirements:
  * CUDA or CPU support for neural network computations (Torch).

## 2. Project Structure Related to Build and Usage

* `pyproject.toml`: Contains project metadata, main dependencies, build system configuration using Hatchling, developer dependency groups (dev), and wheel package targets.
* `uv.lock`: Lockfile containing detailed package dependency specifications generated by `uv`.
* `configs/`: Directory containing YAML configuration files:
  * `configs/base.yaml`: General configuration such as target device (`cuda`), random seed, and output directory `artifacts`.
  * `configs/data.yaml`: Configuration for training dataset paths, YCB dataset paths, YCB object IDs (`003_cracker_box`, `004_sugar_box`, `006_mustard_bottle`), and dataset splits.
  * `configs/model.yaml`: Configuration for Generative Grasping model architecture (generative model type `diffusion`, number of steps, hidden dimensions) and RL model.
  * `configs/training.yaml`: Configuration for training hyperparameters (supervised training and reinforcement learning).
  * `configs/evaluation.yaml`: Configuration for evaluation metrics such as friction coefficient and minimum lift height threshold.
  * `configs/robot.yaml`: Configuration related to the robot, gripper, and inverse kinematics (IK).
  * `configs/simulation.yaml`: Configuration for physics simulation time-step and simulation steps.
* `scripts/`: Contains Python scripts for running various tasks:
  * `scripts/prepare_data.py`: Discovers and indexes the dataset records.
  * `scripts/train.py`: Trains the grasp-pose generation model using supervised learning.
  * `scripts/train_rl.py`: Trains the grasping policy using reinforcement learning (RL).
  * `scripts/generate_grasps.py`: Generates grasp poses from object point clouds.
  * `scripts/run_simulation.py`: Executes generated grasps in a MuJoCo simulation environment.
  * `scripts/evaluate.py`: Evaluates the generated grasp poses.
* `src/grasping_ai/`: Main source code directory containing functional modules.
* `deploy/`: Contains robot and gripper description XML files (`deploy/robot.xml` and `deploy/gripper.xml`) for the MuJoCo simulation.

## 3. Environment Setup

To set up the environment and install the required libraries, follow these steps:

Create a virtual environment using `uv`:
```bash
uv venv
```

Activate the virtual environment:
* On Windows:
```powershell
.venv\Scripts\activate
```
* On Linux/macOS:
```bash
source .venv/bin/activate
```

Install dependencies and the project in editable mode:
```bash
uv pip install -e .
```

To synchronize the entire environment including development packages (such as `pytest`, `ruff`, `mypy`, `mujoco` defined in `[dependency-groups]` of `pyproject.toml`), run:
```bash
uv sync
```

## 4. Building the Project

* Build Backend: The project uses `hatchling.build` as the build backend, declared in `pyproject.toml`.
* Build Tool: Use compatible tools or `hatch` / `uv build`.
* Package Build Command:
```bash
uv build
```
* Output Directory: The `dist/` directory will contain the generated artifacts, including the wheel package (`.whl`) and source distribution (`.tar.gz`). These files can be used for distribution or installing the project on other systems.

The project supports running directly in editable mode using `uv pip install -e .` or via `uv run` without requiring a manual package build.

## 5. Running the Source Code

The project does not register CLI commands under console scripts in `pyproject.toml`. Execution is performed by directly invoking the Python scripts inside the `scripts/` directory.

The scripts accept the following command-line arguments:

### 5.1 Preparing the Dataset Index
This command searches for dataset records and writes a dataset index file.
```bash
python scripts/prepare_data.py --dataset-root <path_to_raw_dataset> --output-index <path_to_output_index_file>
```
* Arguments:
  * `--dataset-root`: Path to the directory containing raw dataset records.
  * `--output-index`: Path where the generated index file will be saved.

### 5.2 Training the Grasp-Generation Model (Supervised Training)
```bash
python scripts/train.py --dataset-root <path_to_processed_dataset> --checkpoint <path_to_save_checkpoint> --feature-dim 128 --hidden-dim 256 --num-layers 4 --learning-rate 0.0001 --num-epochs 100 --batch-size 32 --device cuda
```
* Arguments:
  * `--dataset-root`: Root directory of the processed grasp-pose dataset.
  * `--checkpoint`: Destination path for the trained model checkpoint.
  * `--feature-dim`: Conditioning feature dimension used by the encoder (e.g., `128`).
  * `--hidden-dim`: Hidden width of the grasp-generation model (e.g., `256`).
  * `--num-layers`: Number of layers in the model (e.g., `4`).
  * `--learning-rate`: Learning rate for the optimizer (e.g., `0.0001`).
  * `--num-epochs`: Number of training epochs to perform (e.g., `100`).
  * `--batch-size`: Training batch size (e.g., `32`).
  * `--device`: Device identifier (`cuda` or `cpu`).

### 5.3 Training the RL Grasping Policy (RL Training)
```bash
python scripts/train_rl.py --robot-xml deploy/robot.xml --ycb-root data/raw/ycb --object-ids 003_cracker_box --policy-checkpoint <path_to_save_policy_checkpoint> --observation-dim 64 --action-dim 7 --hidden-dim 256 --learning-rate 0.0003 --num-updates 1000 --gamma 0.99 --device cuda
```
* Arguments:
  * `--robot-xml`: Path to the robot MJCF description used in training.
  * `--ycb-root`: Root directory of the YCB object set.
  * `--object-ids`: YCB object identifiers used during training rollouts (space-separated).
  * `--policy-checkpoint`: Destination path for the trained policy checkpoint.
  * `--observation-dim`: Dimensionality of the policy observation vector.
  * `--action-dim`: Dimensionality of the policy action vector.
  * `--hidden-dim`: Hidden width of the policy and value networks.
  * `--learning-rate`: Learning rate for the policy optimizer.
  * `--num-updates`: Number of policy update steps to perform.
  * `--gamma`: Discount factor for return computation.
  * `--device`: Device identifier (`cuda` or `cpu`).

### 5.4 Generating Grasps (Grasp Generation)
```bash
python scripts/generate_grasps.py --checkpoint <path_to_model_checkpoint> --observations <path_to_observation_1> <path_to_observation_2> --output <path_to_save_grasps_file> --feature-dim 128 --num-diffusion-steps 100 --num-grasps 10 --device cuda
```
* Arguments:
  * `--checkpoint`: Path to the trained grasp-generation model checkpoint.
  * `--observations`: One or more paths to per-object sensor observations (e.g., `.npy` files).
  * `--output`: Destination path for the generated-grasp output file (e.g., `.npy` file).
  * `--feature-dim`: Conditioning feature dimension expected by the model.
  * `--num-diffusion-steps`: Number of denoising steps used at inference.
  * `--num-grasps`: Number of candidate grasps to generate per object.
  * `--device`: Device identifier (`cuda` or `cpu`).

### 5.5 Running Grasps in MuJoCo Simulation
```bash
python scripts/run_simulation.py --grasps <path_to_grasps_file> --object-id 003_cracker_box --ycb-root data/raw/ycb --robot-xml deploy/robot.xml --table-xml <path_to_table_xml> --output <path_to_save_outcomes_json> --num-simulation-steps 500 --gripper-close-command 1.0 1.0
```
* Arguments:
  * `--grasps`: Path to a file containing grasp poses to execute (file `.npy`).
  * `--object-id`: Logical YCB object identifier to load.
  * `--ycb-root`: Root directory of the YCB object set.
  * `--robot-xml`: Path to the robot MJCF description.
  * `--table-xml` (Optional): Path to a workbench/table MJCF description.
  * `--output`: Destination path for the simulation outcomes (JSON format).
  * `--num-simulation-steps`: Number of physics steps per grasp attempt.
  * `--gripper-close-command`: Gripper command used to close the gripper (space-separated list of float values).

### 5.6 Evaluating Grasps (Evaluation)
```bash
python scripts/evaluate.py --grasps <path_to_grasps_file> --object-id 003_cracker_box --object-point-cloud <path_to_object_pc_npy> --gripper-point-cloud <path_to_gripper_pc_npy> --report <path_to_save_report_json> --friction-coefficient 0.5 --lift-height-threshold 0.05
```
* Arguments:
  * `--grasps`: Path to the generated grasp poses file to evaluate.
  * `--object-id`: Identifier of the object whose grasps are being evaluated.
  * `--object-point-cloud`: Path to the object point cloud file (`.npy`).
  * `--gripper-point-cloud`: Path to the gripper point cloud file (`.npy`).
  * `--report`: Destination path for the evaluation report (JSON format).
  * `--friction-coefficient`: Friction coefficient used in force-closure checks.
  * `--lift-height-threshold`: Height threshold used for lift-success checks.

## 6. Configuration

The project stores reference experiment settings as YAML files in the `configs/` directory. These files are documentation/default templates, not runtime-loaded configuration: the CLI scripts and pipeline functions accept parameters directly via explicit arguments. The main reference settings documented are:

* General Config (`base.yaml`):
  * `seed`: Random seed (Default: `0`).
  * `device`: Computation device (Default: `cuda`).
  * `output_dir`: Output directory for generated artifacts (Default: `artifacts`).
  * `experiment_name`: Experiment name identifier (Default: `default`).
* Data Config (`data.yaml`):
  * `dataset_root`: Directory for processed dataset (Default: `data/processed`).
  * `ycb_root`: Directory for raw YCB object dataset (Default: `data/raw/ycb`).
  * `object_ids`: List of YCB objects for training/testing (Default: `003_cracker_box`, `004_sugar_box`, `006_mustard_bottle`).
  * `train_split`, `val_split`, `test_split`: Data split names (Default: `train`, `val`, `test`).
* Model Config (`model.yaml`):
  * `model_type`: Generative model type (Default: `diffusion`).
  * `feature_dim`, `hidden_dim`, `num_layers`: Network architecture parameters.
  * `grasp_dim`: Grasp pose dimensionality (Default: `7` - representing position and quaternion orientation).
  * `num_diffusion_steps`, `num_flow_steps`: Number of steps for diffusion/flow pipelines.
* Training Config (`training.yaml`):
  * `batch_size`: Default `32`.
  * `learning_rate`: Default `0.0001`.
  * `num_epochs`: Default `100`.
  * `rl_learning_rate`: Learning rate for RL policy (Default: `0.0003`).
  * `rl_num_updates`: Number of policy update steps (Default: `1000`).
* Evaluation Config (`evaluation.yaml`):
  * `friction_coefficient`: Friction coefficient for force-closure (Default: `0.5`).
  * `lift_height_threshold`: Minimum lift height for grasp success (Default: `0.05`).
* Robot Config (`robot.yaml`):
  * `robot_description_path`: Robot XML file path (Default: `deploy/robot.xml`).
  * `gripper_description_path`: Gripper XML file path (Default: `deploy/gripper.xml`).
* Simulation Config (`simulation.yaml`):
  * `simulation_dt`: Physics simulation time-step delta (Default: `0.002`).
  * `num_simulation_steps`: Number of steps per grasp evaluation (Default: `500`).

## 7. Typical Workflow

Here is a complete workflow from environment setup to grasp evaluation:

1. **Setup and activate environment**:
```bash
uv venv
source .venv/bin/activate
uv sync
```

2. **Index raw dataset**:
```bash
python scripts/prepare_data.py --dataset-root data/raw/grasp_data --output-index data/processed/index.json
```

3. **Train the grasp pose generation model**:
```bash
python scripts/train.py --dataset-root data/processed --checkpoint artifacts/checkpoints/diffusion_model.pt --feature-dim 128 --hidden-dim 256 --num-layers 4 --learning-rate 0.0001 --num-epochs 50 --batch-size 32 --device cuda
```

4. **Generate candidate grasp poses from observations**:
```bash
python scripts/generate_grasps.py --checkpoint artifacts/checkpoints/diffusion_model.pt --observations data/processed/obs_0.npy --output artifacts/exports/generated_grasps.npy --feature-dim 128 --num-diffusion-steps 100 --num-grasps 10 --device cuda
```

5. **Run grasp execution simulation in MuJoCo**:
```bash
python scripts/run_simulation.py --grasps artifacts/exports/generated_grasps.npy --object-id 003_cracker_box --ycb-root data/raw/ycb --robot-xml deploy/robot.xml --output artifacts/reports/simulation_outcomes.json --num-simulation-steps 500 --gripper-close-command 1.0 1.0
```

6. **Evaluate grasp qualities and generate report**:
```bash
python scripts/evaluate.py --grasps artifacts/exports/generated_grasps.npy --object-id 003_cracker_box --object-point-cloud data/processed/object_pc.npy --gripper-point-cloud data/processed/gripper_pc.npy --report artifacts/reports/evaluation_report.json --friction-coefficient 0.5 --lift-height-threshold 0.05
```

## 8. Troubleshooting

* Module missing or `grasping_ai` not found:
  * Symptom: Raising `ModuleNotFoundError: No module named 'grasping_ai'` when executing scripts.
  * Cause: The package is not installed in editable mode or the virtual environment is not activated.
  * How to check: Run `uv pip list` to verify if `vr-rlft-side-project` points to the current directory.
  * Solution: Run `uv pip install -e .` in the project root directory after activating the virtual environment.

* CUDA device unavailable:
  * Symptom: PyTorch halts or raises errors when passing `--device cuda`.
  * Cause: NVIDIA drivers or the installed PyTorch version do not support CUDA on the current hardware.
  * How to check: Execute `python -c "import torch; print(torch.cuda.is_available())"` to check CUDA availability.
  * Solution: Reinstall PyTorch with the correct CUDA version, or fall back to `--device cpu`.
