# User Guide

## 1. Environment Requirements

* Python Version: Requires Python version `3.12` or higher (specified in `.python-version` and `requires-python` in `pyproject.toml`).
* Operating System: No specific operating system requirements are defined in the source code or configurations. However, standard Python running environments are supported.
* Prerequisites:
  * Package and virtual environment manager `uv` (as the project uses `uv.lock` for dependency management).
* Other hardware/software requirements:
  * CUDA or CPU support for neural network computations (Torch).

## 2. Project Structure Related to Build and Usage

* `pyproject.toml`: Contains project metadata, main dependencies, build system configuration using Hatchling, developer dependency groups (dev), and wheel package targets.
* `uv.lock`: Lockfile containing detailed package dependency specifications generated by `uv`.
* `configs/`: Hydra configuration tree loaded by CLI scripts via ``grasping_ai.config.yaml_loader``. Pass ``--config-dir`` to point at another directory; Hydra dot-notation overrides (``seed=100``) and explicit CLI flags override config values.
  * `configs/config.yaml`: Hydra entrypoint composing all config groups.
  * `configs/base.yaml`: Device, seed, experiment name, and tracking settings.
  * `configs/data/default.yaml`: Unified dataset paths, synthetic-data generation, and observation sampling.
  * `configs/model/default.yaml`: Alias to `model/diffusion.yaml` (default generative method).
  * `configs/model/diffusion.yaml`: Diffusion architecture, checkpoints, and export paths.
  * `configs/model/flow.yaml`: Flow-matching architecture, checkpoints, and export paths.
  * `configs/training/diffusion.yaml` or `configs/training/flow.yaml`: Supervised training hyperparameters; `default.yaml` aliases diffusion.
  * `configs/rl/default.yaml`: RL policy architecture, PPO hyperparameters, and reward terms.
  * `configs/evaluation/default.yaml`: Shared metrics/limits and default method alias (diffusion).
  * `configs/gripper/default.yaml`: Alias to `gripper/franka_emika_panda.yaml`.
  * `configs/gripper/franka_emika_panda.yaml`: Franka Emika Panda MJCF path, gripper commands, and IK settings.
  * `configs/env/default.yaml`: MuJoCo simulation step count and timestep.
* `scripts/`: Contains Python scripts for running various tasks:
  * `scripts/prepare_data.py`: Discovers dataset records and (with `--mode synthetic`) generates synthetic grasp datasets from YCB meshes.
  * `scripts/prepare_ycb_mjcf.py`: Writes thin MuJoCo object wrappers for objects whose shipped description is OpenRAVE KinBody XML.
  * `scripts/prepare_observations.py`: Samples per-object observation point clouds and a simple gripper cloud for inference/evaluation.
  * `scripts/extract_object_grasps.py`: Extracts a single object's grasp poses from the dict-format generated-grasps file.
  * `scripts/train_diffusion.py`: Trains the diffusion grasp-generation model using supervised learning.
  * `scripts/train_rl.py`: Trains the grasping policy using Stable-Baselines3 PPO against the Gymnasium-compatible MuJoCo environment.
  * `scripts/generate_grasps.py`: Generates grasp poses from object point clouds.
  * `scripts/run_simulation.py`: Executes generated grasps in a MuJoCo simulation environment.
  * `scripts/visualize_robot.py`: Opens an interactive MuJoCo viewer.
  * `scripts/evaluate.py`: Evaluates the generated grasp poses (analytical: collision-free + force-closure ⇒ `grasp_success`).
  * `scripts/run_artifacts.py`: End-to-end reproducible artifact chain (MJCF YCB → synthetic data → training → grasp generation → MuJoCo → evaluation → RL → policy inference); writes `artifacts/manifest.jsonl`.
* `src/grasping_ai/`: Main source code directory containing functional modules.
* `deploy/`: Contains the Franka Emika Panda MJCF (`deploy/robot.xml`) and Menagerie meshes under `deploy/franka_emika_panda/`. The Panda hand is integrated into the same MJCF; there is no separate `deploy/gripper.xml`.

## 3. Environment Setup

To set up the environment and install the required libraries, follow these steps:

Create a virtual environment using `uv`:
```bash
uv venv
```

Activate the virtual environment:
* On Windows:
```powershell
.venv\Scripts\activate
```
* On Linux/macOS:
```bash
source .venv/bin/activate
```

Install dependencies and the project in editable mode:
```bash
uv pip install -e .
```

To synchronize the entire environment including development packages (such as `pytest`, `ruff`, `mypy`, `mujoco` defined in `[dependency-groups]` of `pyproject.toml`), run:
```bash
uv sync
```

## 4. Building the Project

* Build Backend: The project uses `hatchling.build` as the build backend, declared in `pyproject.toml`.
* Build Tool: Use compatible tools or `hatch` / `uv build`.
* Package Build Command:
```bash
uv build
```
* Output Directory: The `dist/` directory will contain the generated artifacts, including the wheel package (`.whl`) and source distribution (`.tar.gz`). These files can be used for distribution or installing the project on other systems.

The project supports running directly in editable mode using `uv pip install -e .` or via `uv run` without requiring a manual package build.

## 5. Running the Source Code

The project does not register CLI commands under console scripts in `pyproject.toml`. Execution is performed by directly invoking the Python scripts inside the `scripts/` directory.

The scripts accept the following command-line arguments:

### 5.1 Preparing the Dataset Index
This command searches for dataset records and writes a dataset index file.
```bash
python scripts/prepare_data.py --dataset-root <path_to_raw_dataset> --output-index <path_to_output_index_file>
```
* Arguments:
  * `--dataset-root`: Path to the directory containing raw dataset records.
  * `--output-index`: Path where the generated index file will be saved.

### 5.2 Training the Grasp-Generation Model (Supervised Training)
```bash
python scripts/train_diffusion.py --dataset-root <path_to_processed_dataset> --checkpoint <path_to_save_checkpoint> --feature-dim 128 --hidden-dim 256 --num-layers 4 --learning-rate 0.0001 --num-epochs 100 --batch-size 32 --device cuda
```
* Arguments:
  * `--dataset-root`: Root directory of the processed grasp-pose dataset.
  * `--checkpoint`: Destination path for the trained model checkpoint.
  * `--feature-dim`: Conditioning feature dimension used by the encoder (e.g., `128`).
  * `--hidden-dim`: Hidden width of the grasp-generation model (e.g., `256`).
  * `--num-layers`: Number of layers in the model (e.g., `4`).
  * `--learning-rate`: Learning rate for the optimizer (e.g., `0.0001`).
  * `--num-epochs`: Number of training epochs to perform (e.g., `100`).
  * `--batch-size`: Training batch size (e.g., `32`).
  * `--device`: Device identifier (`cuda` or `cpu`).

### 5.3 Training the RL Grasping Policy (RL Training)

The RL pipeline uses Stable-Baselines3 PPO against the Gymnasium-compatible `MuJoCoGraspingEnv`. Observation and action dimensions depend on the composed MuJoCo scene (robot + YCB object), so they must match the environment's actual space. With the shipped Franka Panda `deploy/robot.xml` and one freejoint YCB object, the pipeline expects `observation-dim=31` and `action-dim=8`; other robots/YCB combinations require recomputation.

```bash
python scripts/train_rl.py --robot-xml deploy/robot.xml --ycb-root data/processed/ycb_mjcf --object-ids 003_cracker_box --policy-checkpoint <path_to_save_policy_checkpoint> --observation-dim 31 --action-dim 8 --hidden-dim 256 --learning-rate 0.0003 --num-updates 1000 --gamma 0.99 --device cuda
```
* Arguments:
  * `--robot-xml`: Path to the robot MJCF description used in training.
  * `--ycb-root`: Root directory of the YCB object set (use `data/processed/ycb_mjcf` for the generated MuJoCo wrappers).
  * `--object-ids`: YCB object identifiers used during training rollouts (space-separated). The environment tracks a single object body, so at most one identifier must be supplied; the pipeline raises `ValueError` otherwise.
  * `--policy-checkpoint`: Destination path for the trained policy checkpoint.
  * `--observation-dim`: Dimensionality of the policy observation vector (must match the Gymnasium environment's `observation_space`).
  * `--action-dim`: Dimensionality of the policy action vector (must match the Gymnasium environment's `action_space`).
  * `--hidden-dim`: Hidden width of the policy and value networks.
  * `--learning-rate`: Learning rate for the policy optimizer.
  * `--num-updates`: Number of policy update steps to perform.
  * `--gamma`: Discount factor for return computation.
  * `--seed`: Optional random seed for reproducible policy initialization.
  * `--experiment-log-dir`: Optional path to write TensorBoard experiment events.
  * `--device`: Device identifier (`cuda` or `cpu`).

### 5.4 Generating Grasps (Grasp Generation)
```bash
python scripts/generate_grasps.py --checkpoint <path_to_model_checkpoint> --observations <path_to_observation_1> <path_to_observation_2> --output <path_to_save_grasps_file> --feature-dim 128 --num-diffusion-steps 100 --num-grasps 10 --device cuda
```
* Arguments:
  * `--checkpoint`: Path to the trained grasp-generation model checkpoint.
  * `--observations`: One or more paths to per-object sensor observations (e.g., `.npy` files).
  * `--output`: Destination path for the generated-grasp output file (e.g., `.npy` file).
  * `--feature-dim`: Conditioning feature dimension expected by the model.
  * `--num-diffusion-steps`: Number of denoising steps used at inference.
  * `--num-grasps`: Number of candidate grasps to generate per object.
  * `--device`: Device identifier (`cuda` or `cpu`).

### 5.5 Running Grasps in MuJoCo Simulation
```bash
python scripts/run_simulation.py --grasps <path_to_grasps_file> --object-id 003_cracker_box --ycb-root data/processed/ycb_mjcf --robot-xml deploy/robot.xml --table-xml <path_to_table_xml> --output <path_to_save_outcomes_json> --num-simulation-steps 500 --gripper-close-command 0
```
* Arguments:
  * `--grasps`: Path to a file containing grasp poses to execute (file `.npy`).
  * `--object-id`: Logical YCB object identifier to load.
  * `--ycb-root`: Root directory of the YCB object set.
  * `--robot-xml`: Path to the robot MJCF description.
  * `--table-xml` (Optional): Path to a workbench/table MJCF description.
  * `--output`: Destination path for the simulation outcomes (JSON format).
  * `--num-simulation-steps`: Number of physics steps per grasp attempt.
  * `--gripper-close-command`: Gripper command used to close the gripper (space-separated list of float values). For the shipped Franka Panda, this overlays the hand actuator (`0` closed, `255` open); use `0` to close.

### 5.5b Visualizing and Controlling the Robot

Grasp execution stays in `scripts/run_simulation.py`. Open the viewer first, then run the TUI in a second terminal (no arguments, no extra window):

```bash
python scripts/visualize_robot.py --robot-xml deploy/robot.xml
```

`visualize_robot.py` opens MuJoCo and listens on UDP topic `robot/keyboard` (`127.0.0.1:5511`). The keyboard-topic module is a terminal publisher only. Keys: `1-9` select an actuator, left/right nudge it, `g` toggles the gripper, `h` returns home, space pauses, `q` quits the TUI.

### 5.6 Evaluating Grasps (Evaluation)
```bash
python scripts/evaluate.py --grasps <path_to_grasps_file> --object-id 003_cracker_box --object-point-cloud <path_to_object_pc_npy> --gripper-point-cloud <path_to_gripper_pc_npy> --report <path_to_save_report_json> --friction-coefficient 0.5 --lift-height-threshold 0.05
```
* Arguments:
  * `--grasps`: Path to the generated grasp poses file to evaluate.
  * `--object-id`: Identifier of the object whose grasps are being evaluated.
  * `--object-point-cloud`: Path to the object point cloud file (`.npy`).
  * `--gripper-point-cloud`: Path to the gripper point cloud file (`.npy`).
  * `--report`: Destination path for the evaluation report (JSON format).
  * `--friction-coefficient`: Friction coefficient used in force-closure checks.
  * `--lift-height-threshold`: Height threshold used for lift-success checks.

## 6. Configuration

The project stores experiment defaults as a Hydra config tree in `configs/`. CLI scripts compose ``configs/config.yaml`` through ``grasping_ai.config.yaml_loader``. Use ``--config-dir`` to select another config directory, Hydra overrides such as ``seed=100`` or ``supervised.learning_rate=0.0005``, or explicit CLI flags to override YAML values.

The main settings use nested objects (not flat prefix keys):

* General Config (`base.yaml`):
  * `seed`, `device`, `experiment_name`, `tracking.*`
  * `paths.output_dir`, `paths.ycb_mjcf`, `paths.observations`, `paths.tensorboard`
* Data Config (`data/default.yaml`):
  * `paths.checkpoints`, `paths.exports`, `paths.reports`, `paths.tensorboard` (under `paths.output_dir`)
  * `synthetic.gripper_width` → `${robot.gripper.max_width}`; `synthetic.friction_coefficient` / `collision_clearance` → `${metrics.*}`
  * `objects.ids`: YCB object list
  * `synthetic.*`: synthetic dataset generation
  * `observations.*`: observation cloud sampling
* Model Config (`model/diffusion.yaml` or `model/flow.yaml`; `model/default.yaml` selects diffusion):
  * `default_method`: `diffusion` or `flow`
  * `architecture.feature_dim`, `architecture.hidden_dim`, `architecture.num_layers`, `architecture.num_grasps`
  * `grasp.dim`, `grasp.representation` (shared `model/grasp.yaml`)
  * `diffusion.inference_steps`, `diffusion.num_steps`, `diffusion.checkpoint`, `diffusion.tensorboard`, `diffusion.exports.*` (paths via `${paths.*}`, object id via `${objects.ids.0}`)
  * `flow.*`: same shape as `diffusion`
  * `rl.observation_dim`, `rl.action_dim`, `rl.hidden_dim`, `rl.checkpoint`, `rl.tensorboard`
* Training Config (`training/diffusion.yaml` or `training/flow.yaml`; `training/default.yaml` selects diffusion):
  * `supervised.batch_size`, `supervised.learning_rate`, `supervised.num_epochs`
* RL Config (`rl/default.yaml`):
  * `rl.learning_rate`, `rl.num_updates`, `rl.gamma`
  * `rl.reward.lift_height_threshold` → `${metrics.lift_height_threshold}`
* Evaluation Config (`evaluation/default.yaml` holds shared metrics/limits; `diffusion.yaml`, `flow.yaml`, `rl.yaml` add method settings):
  * Common: `metrics.friction_coefficient`, `metrics.lift_height_threshold`, `metrics.collision_clearance`, `metrics.wrench_regularization`, `limits.max_linear_velocity`, `limits.max_angular_velocity`
  * Method: `evaluation.method`, `evaluation.analytical_report`, `evaluation.simulation_report` (generative); `evaluation.rollout_report`, `evaluation.episodes`, `evaluation.max_steps` (RL)
* Gripper Config (`gripper/franka_emika_panda.yaml`; `gripper/default.yaml` selects Franka):
  * `robot.description`, `robot.gripper.close_command`, `robot.gripper.open_command`, `robot.ik.max_iterations`, `robot.ik.tolerance`
* Env Config (`env/default.yaml`):
  * `dt`, `num_steps`, `table_xml`

## 7. Typical Workflow

The project ships a reproducible end-to-end artifact runner that exercises the complete supervised and RL chains against the real YCB assets in a single command:

```bash
python scripts/run_artifacts.py
```

It writes a manifest of the executed commands and the retained artifacts to `artifacts/manifest.jsonl`. The generated artifacts themselves (checkpoints, processed dataset, reports, MJCF wrappers) are excluded from version control by `.gitignore` and are produced from source on demand by this script.

For manual execution, the equivalent step sequence is:

1. **Setup and activate environment**:
```bash
uv venv
source .venv/bin/activate
uv sync
```

2. **Build MJCF wrappers for YCB objects** (the shipped YCB descriptions are OpenRAVE KinBody, not MuJoCo):
```bash
python scripts/prepare_ycb_mjcf.py --ycb-root data/raw/ycb --output-root data/processed/ycb_mjcf
```

3. **Generate synthetic dataset and index**:
```bash
python scripts/prepare_data.py --mode synthetic --ycb-root data/raw/ycb --dataset-root data/processed --output-index data/processed/index.json --num-samples 256 --num-grasps 8 --gripper-width 0.08 --seed 42
```

4. **Sample per-object observation point clouds**:
```bash
python scripts/prepare_observations.py --ycb-root data/raw/ycb --output-dir data/observations --num-samples 256 --seed 7
```

5. **Train the grasp pose generation model**:
```bash
python scripts/train_diffusion.py --dataset-root data/processed --checkpoint artifacts/checkpoints/diffusion_grasp_generator.pt --feature-dim 32 --hidden-dim 32 --num-layers 2 --learning-rate 0.001 --num-epochs 3 --batch-size 2 --device cpu --seed 42
```

6. **Generate candidate grasp poses from observations**:
```bash
python scripts/generate_grasps.py --checkpoint artifacts/checkpoints/diffusion_grasp_generator.pt --observations data/observations/003_cracker_box.npy data/observations/004_sugar_box.npy data/observations/006_mustard_bottle.npy --output artifacts/exports/diffusion_grasp_candidates_by_object.npy --feature-dim 32 --num-diffusion-steps 5 --num-grasps 8 --device cpu
```

7. **Run grasp execution simulation in MuJoCo** (requires per-object pose arrays — see `scripts/extract_object_grasps.py`):
```bash
python scripts/extract_object_grasps.py --input artifacts/exports/diffusion_grasp_candidates_by_object.npy --output artifacts/exports/diffusion_grasp_poses_003_cracker_box.npy --key object_0
python scripts/run_simulation.py --grasps artifacts/exports/diffusion_grasp_poses_003_cracker_box.npy --object-id 003_cracker_box --ycb-root data/processed/ycb_mjcf --robot-xml deploy/robot.xml --output artifacts/reports/diffusion_simulation_outcomes_003_cracker_box.jsonl --num-simulation-steps 50 --gripper-close-command 0
```

8. **Evaluate grasp qualities and generate report** (offline analytical: collision-free + force-closure ⇒ `grasp_success`):
```bash
python scripts/evaluate.py --grasps artifacts/exports/diffusion_grasp_candidates_by_object.npy --object-id object_1 --object-point-cloud data/observations/004_sugar_box.npy --gripper-point-cloud data/observations/gripper.npy --report artifacts/reports/diffusion_analytical_evaluation_report.jsonl --friction-coefficient 0.5 --lift-height-threshold 0.05
```

9. **Train the RL grasping policy via Stable-Baselines3 PPO**:
```bash
python scripts/train_rl.py --robot-xml deploy/robot.xml --ycb-root data/processed/ycb_mjcf --object-ids 003_cracker_box --policy-checkpoint artifacts/checkpoints/rl_grasp_policy.pt --observation-dim 31 --action-dim 8 --hidden-dim 32 --learning-rate 0.0003 --num-updates 10 --gamma 0.99 --device cpu --seed 42
```

**Artifact naming:** outputs are prefixed by method so diffusion, flow, and RL artifacts do not collide.

| Kind | Diffusion | Flow | RL |
| ---- | --------- | ---- | -- |
| Checkpoint | `diffusion_grasp_generator.pt` | `flow_grasp_generator.pt` | `rl_grasp_policy.pt` |
| Multi-object grasps | `diffusion_grasp_candidates_by_object.npy` | `flow_grasp_candidates_by_object.npy` | — |
| Runtime workflow (`run_workflow.py`) | `{method}_grasp_candidates.npy`, `{method}_simulation_outcomes.jsonl`, `{method}_analytical_evaluation_report.jsonl` | same pattern | `rl_grasp_rollout_report.jsonl` |

## 8. Troubleshooting

* Module missing or `grasping_ai` not found:
  * Symptom: Raising `ModuleNotFoundError: No module named 'grasping_ai'` when executing scripts.
  * Cause: The package is not installed in editable mode or the virtual environment is not activated.
  * How to check: Run `uv pip list` to verify if `vr-rlft-side-project` points to the current directory.
  * Solution: Run `uv pip install -e .` in the project root directory after activating the virtual environment.

* CUDA device unavailable:
  * Symptom: PyTorch halts or raises errors when passing `--device cuda`.
  * Cause: NVIDIA drivers or the installed PyTorch version do not support CUDA on the current hardware.
  * How to check: Execute `python -c "import torch; print(torch.cuda.is_available())"` to check CUDA availability.
  * Solution: Reinstall PyTorch with the correct CUDA version, or fall back to `--device cpu`.
