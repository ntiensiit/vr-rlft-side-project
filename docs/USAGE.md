# User Guide

## 1. Environment Requirements

* Python Version: Requires Python version `3.12` or higher (specified in `.python-version` and `requires-python` in `pyproject.toml`).
* Operating System: No specific operating system requirements are defined in the source code or configurations. However, standard Python running environments are supported.
* Prerequisites:
  * Package and virtual environment manager `uv` (as the project uses `uv.lock` for dependency management).
* Other hardware/software requirements:
  * CUDA or CPU support for neural network computations (Torch). The lockfile pins CPU wheels (`torch+cpu`); install a CUDA build separately if needed.

## 2. Project Structure Related to Build and Usage

* `pyproject.toml`: Contains project metadata, main dependencies, build system configuration using Hatchling, developer dependency groups (dev), and wheel package targets.
* `uv.lock`: Lockfile containing detailed package dependency specifications generated by `uv`.
* `configs/`: Hydra configuration tree. CLI scripts use `@hydra.main` with `config_path=../configs` and `config_name=scripts/<script>`. Library code composes `configs/project.yaml` through `FlattenedYAMLConfig`. Override with Hydra syntax (`seed=100`, `supervised.learning_rate=0.0005`, `script.object_id=003_cracker_box`).
  * `configs/project.yaml`: Library composition root (base, data, artifacts, gripper, env, object, model, rl, workflow, notebook).
  * `configs/config.yaml`: Thin alias that pulls in `training/diffusion` (used by `scripts/base`).
  * `configs/scripts/<script>.yaml`: Per-CLI entrypoint. Script-local keys live under `script:`.
  * `configs/base.yaml`: Device, seed, experiment name, and tracking settings.
  * `configs/data/default.yaml`: Dataset paths, synthetic-data generation, and observation sampling.
  * `configs/model/default.yaml`: Alias to `model/diffusion.yaml`.
  * `configs/model/diffusion.yaml` / `flow.yaml`: Architecture, checkpoints, and export paths.
  * `configs/model/grasp.yaml`: Shared 9D grasp representation.
  * `configs/training/diffusion.yaml` or `flow.yaml`: Supervised training composition; `supervised.yaml` holds shared hyperparameters.
  * `configs/rl/default.yaml`: RL policy architecture, PPO hyperparameters, and reward terms.
  * `configs/evaluation/default.yaml`: Shared metrics/limits; method variants `diffusion.yaml`, `flow.yaml`, `rl.yaml`.
  * `configs/gripper/default.yaml`: Alias to `gripper/franka_emika_panda.yaml`.
  * `configs/env/default.yaml`: MuJoCo simulation step count and timestep.
  * `configs/artifacts/default.yaml`: Checkpoint, export, report, and TensorBoard roots.
  * `configs/workflow/default.yaml`: Runtime workflow intermediate filenames.
* `scripts/`: Hydra CLI entry points. See the script table in `README.md`.
* `src/grasping_ai/`: Main source code directory containing functional modules.
* `deploy/`: Contains the Franka Emika Panda MJCF (`deploy/robot.xml`) and Menagerie meshes under `deploy/franka_emika_panda/`. The Panda hand is integrated into the same MJCF; there is no separate `deploy/gripper.xml`.

## 3. Environment Setup

To set up the environment and install the required libraries, follow these steps:

Create a virtual environment using `uv`:
```bash
uv venv
```

Activate the virtual environment:
* On Windows:
```powershell
.venv\Scripts\activate
```
* On Linux/macOS:
```bash
source .venv/bin/activate
```

Install dependencies and the project in editable mode:
```bash
uv pip install -e .
```

To synchronize the entire environment including development packages (such as `pytest`, `ruff`, `mypy`, `mujoco` defined in `[dependency-groups]` of `pyproject.toml`), run:
```bash
uv sync
```

## 4. Building the Project

* Build Backend: The project uses `hatchling.build` as the build backend, declared in `pyproject.toml`.
* Build Tool: Use compatible tools or `hatch` / `uv build`.
* Package Build Command:
```bash
uv build
```
* Output Directory: The `dist/` directory will contain the generated artifacts, including the wheel package (`.whl`) and source distribution (`.tar.gz`). These files can be used for distribution or installing the project on other systems.

The project supports running directly in editable mode using `uv pip install -e .` or via `uv run` without requiring a manual package build.

## 5. Running the Source Code

The project does not register console scripts in `pyproject.toml`. Invoke the Python files under `scripts/` directly. Each script loads `configs/scripts/<name>.yaml` and accepts Hydra overrides — not argparse flags.

Inspect the composed tree with Hydra's built-in help:

```bash
uv run python scripts/train_diffusion.py --help
uv run python scripts/train_diffusion.py --cfg job
```

### 5.1 Hydra override style

```bash
# Change a domain key
uv run python scripts/train_diffusion.py supervised.num_epochs=10 seed=7

# Change a script-local key (the `script:` block)
uv run python scripts/run_grasp_inference.py script.observation=data/observations/003_cracker_box.npy

# Swap a config group
uv run python scripts/run_grasp_inference.py model=flow evaluation=flow
```

### 5.2 Preparing the dataset

```bash
uv run python scripts/prepare_ycb_mjcf.py
uv run python scripts/prepare_data.py prepare.mode=synthetic
uv run python scripts/prepare_observations.py
```

Synthetic records are pickle-free `.npz` files under `paths.dataset_root` (default `data/processed`). `prepare.mode=index` rebuilds `index.json` without regenerating grasps.

### 5.3 Training the grasp-generation model

```bash
uv run python scripts/train_diffusion.py
uv run python scripts/train_flow.py
```

Shared supervised knobs live in `configs/training/supervised.yaml` (`supervised.batch_size`, `supervised.learning_rate`, `supervised.num_epochs`). Resume and augmentation are `training.resume` and `training.augment`.

### 5.4 Training the RL grasping policy

The RL pipeline uses Stable-Baselines3 PPO against `MuJoCoGraspingEnv`. Observation and action dimensions must match the composed MuJoCo scene. With the shipped Franka Panda `deploy/robot.xml` and one freejoint YCB object, defaults are `rl.observation_dim=31` and `rl.action_dim=8`. The environment tracks a single object body; the CLI uses `objects.ids[0]`.

```bash
uv run python scripts/train_rl.py
```

### 5.5 Generating grasps

```bash
# Multi-object artifact-chain dict (.npy pickle payload)
uv run python scripts/generate_grasps.py

# Single-object plain (K, 4, 4) array
uv run python scripts/run_grasp_inference.py script.observation=data/observations/003_cracker_box.npy
```

### 5.6 Running grasps in MuJoCo

```bash
uv run python scripts/run_simulation.py
```

Defaults: `script.grasps` from `model.exports.grasp_poses`, `script.object_id` from `objects.ids.0`, gripper close command from `robot.gripper.close_command` (`0` closed for the shipped Panda overlay). Optional table: `script.table_xml=deploy/table.xml` when that asset exists.

### 5.7 Visualizing the robot

```bash
uv run python scripts/visualize_robot.py
uv run python scripts/visualize_robot.py script.object_id=003_cracker_box
```

Opens a MuJoCo passive viewer and steps physics until the window closes. Actuator and simulation controls are the viewer's built-in UI. Grasp execution stays in `scripts/run_simulation.py`.

### 5.8 Evaluating grasps

```bash
uv run python scripts/evaluate.py
uv run python scripts/run_rl_evaluation.py
```

Analytical `grasp_success` is collision-free ∧ force-closure (not a physical lift).

### 5.9 Artifact chain and runtime workflow

```bash
uv run python scripts/run_artifacts.py
uv run python scripts/run_workflow.py
uv run python scripts/print_model_info.py
uv run python scripts/extract_object_grasps.py
```

`run_artifacts.py` writes `artifacts/manifest.jsonl`. `run_workflow.py` subprocesses inference → simulation → evaluation (optional RL rollout).

## 6. Configuration

The main settings use nested objects (not flat prefix keys):

* General (`base.yaml`): `seed`, `device`, `experiment_name`, `tracking.*`, `paths.output_dir`
* Data (`data/default.yaml`): `paths.*`, `objects.ids`, `synthetic.*`, `observations.*`
* Model (`model/diffusion.yaml` or `model/flow.yaml`): `architecture.*`, `grasp.*` (from `model/grasp.yaml`), method checkpoint/export paths
* Training (`training/supervised.yaml`): `supervised.*`, `training.augment`, `training.resume`
* RL (`rl/default.yaml`): `rl.observation_dim`, `rl.action_dim`, `rl.hidden_dim`, PPO knobs, `rl.reward.*`
* Evaluation (`evaluation/default.yaml`): `metrics.*`, `limits.*`; method files add reports and `evaluation.method`
* Gripper (`gripper/franka_emika_panda.yaml`): `robot.description`, `robot.gripper.*`, `robot.ik.*`
* Env (`env/default.yaml`): `dt`, `num_steps`, `table_xml`
* Artifacts (`artifacts/default.yaml`): `artifacts.checkpoints`, `artifacts.exports`, `artifacts.reports`

## 7. Typical Workflow

Reproducible end-to-end artifact runner:

```bash
uv run python scripts/run_artifacts.py
```

It writes a manifest of the executed commands and the retained artifacts to `artifacts/manifest.jsonl`. Generated artifacts (checkpoints, processed dataset, reports, MJCF wrappers) are excluded from version control by `.gitignore`.

For manual execution, the equivalent step sequence is:

1. **Setup and activate environment**:
```bash
uv venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
uv sync
```

2. **Build MJCF wrappers for YCB objects** (the shipped YCB descriptions are OpenRAVE KinBody, not MuJoCo):
```bash
uv run python scripts/prepare_ycb_mjcf.py
```

3. **Generate synthetic dataset and index**:
```bash
uv run python scripts/prepare_data.py prepare.mode=synthetic
```

4. **Sample per-object observation point clouds**:
```bash
uv run python scripts/prepare_observations.py
```

5. **Train the grasp pose generation model**:
```bash
uv run python scripts/train_diffusion.py
```

6. **Generate candidate grasp poses from observations**:
```bash
uv run python scripts/generate_grasps.py
```

7. **Run grasp execution simulation in MuJoCo** (requires per-object pose arrays — see `scripts/extract_object_grasps.py`):
```bash
uv run python scripts/extract_object_grasps.py
uv run python scripts/run_simulation.py
```

8. **Evaluate grasp qualities** (offline analytical: collision-free + force-closure ⇒ `grasp_success`):
```bash
uv run python scripts/evaluate.py
```

9. **Train the RL grasping policy via Stable-Baselines3 PPO**:
```bash
uv run python scripts/train_rl.py
```

**Artifact naming:** outputs are prefixed by method so diffusion, flow, and RL artifacts do not collide.

| Kind | Diffusion | Flow | RL |
| ---- | --------- | ---- | -- |
| Checkpoint | `diffusion_grasp_generator.pt` | `flow_grasp_generator.pt` | `rl_grasp_policy.pt` |
| Multi-object grasps | `diffusion_grasp_candidates_by_object.npy` | `flow_grasp_candidates_by_object.npy` | — |
| Runtime workflow (`run_workflow.py`) | `{method}_grasp_candidates.npy`, `{method}_simulation_outcomes.jsonl`, `{method}_analytical_evaluation_report.jsonl` | same pattern | `rl_grasp_rollout_report.jsonl` |

## 8. Troubleshooting

* Module missing or `grasping_ai` not found:
  * Symptom: Raising `ModuleNotFoundError: No module named 'grasping_ai'` when executing scripts.
  * Cause: The package is not installed in editable mode or the virtual environment is not activated.
  * How to check: Run `uv pip list` to verify if `vr-rlft-side-project` points to the current directory.
  * Solution: Run `uv pip install -e .` in the project root directory after activating the virtual environment.

* CUDA device unavailable:
  * Symptom: PyTorch halts or raises errors when passing `device=cuda`.
  * Cause: NVIDIA drivers or the installed PyTorch version do not support CUDA on the current hardware. The lockfile pins CPU wheels.
  * How to check: Execute `python -c "import torch; print(torch.cuda.is_available())"` to check CUDA availability.
  * Solution: Reinstall PyTorch with the correct CUDA version, or keep `device=cpu`.

* Unknown argparse flags such as `--dataset-root`:
  * Symptom: Hydra reports an unknown argument.
  * Cause: CLIs no longer use argparse. Use Hydra overrides (`paths.dataset_root=...`, `script.observation=...`).
